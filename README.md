# LevelUp

Онлайн-платформа для обучения IT (React + Vite) с backend API (Express + SQLite): регистрация и вход, курсы и уроки, отзывы, подписки PRO / AI PRO, панель администратора.

## Быстрый запуск

1. Скопируйте переменные окружения и заполните их:

```bash
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
```

2. Установите зависимости:

```bash
npm install
npm --prefix backend install
```

3. Запустите backend:

```bash
npm run backend:dev
```

4. Запустите frontend (в другом терминале):

```bash
npm run dev
```

Для локальной разработки укажите в `frontend/.env` `VITE_API_BASE_URL=http://localhost:8787`.

### Администратор (единственный аккаунт)

**Создание.** Задайте `ADMIN_EMAIL` и `ADMIN_INITIAL_PASSWORD` (минимум 8 символов) в `backend/.env` локально или в разделе *Environment* на Render, затем запустите / задеплойте backend. При старте сервер создаёт администратора **только если его ещё нет в базе**. После первого входа смените пароль в *Admin → Settings → Security* и удалите `ADMIN_INITIAL_PASSWORD`.

- Изменение `ADMIN_INITIAL_PASSWORD` не меняет пароль уже существующего администратора — для этого используйте смену пароля в админке или «Forgot Password?».
- Администратор может быть только один: роль Admin есть лишь у `ADMIN_EMAIL`, все остальные аккаунты при старте понижаются до User, а в базе стоит уникальный индекс `idx_user_profiles_single_admin`, который физически не даёт создать вторую запись с ролью Admin. Публичной регистрации администратора нет; регистрация на `ADMIN_EMAIL` отклоняется (409), а назначить роль Admin через API нельзя.
- Сменить email администратора можно только через `ADMIN_EMAIL` (на сервере), а не из интерфейса.

**Вход:** `/admin/login`. Неавторизованный посетитель или обычный пользователь, открывший `/admin`, перенаправляется на эту страницу; admin API отвечает 401 без сессии и 403 для обычного пользователя.

**Восстановление пароля:** `/admin/login` → «Forgot Password?» → письмо со ссылкой `/admin/reset-password?token=…`. Токен — 48 случайных байт, в базе хранится только его SHA-256, срок жизни 30 минут, одноразовый (атомарно), запросы ограничены по IP (`PASSWORD_RESET_RATE_LIMIT_MAX`, по умолчанию 10 в час). Ответ не раскрывает, существует ли email. После сброса все сессии отзываются и приходит письмо-подтверждение.

**Почта.** Для реальной отправки писем задайте `EMAIL_HOST`, `EMAIL_PORT` (587 — STARTTLS, 465 — SSL), `EMAIL_USER`, `EMAIL_PASS`, `EMAIL_FROM` и `FRONTEND_URL` (адрес сайта для ссылок). Для Gmail нужен «пароль приложения» (обычный пароль не подойдёт). Если SMTP не задан, письма **не отправляются**, а ссылка сброса пишется в лог сервера (виден только оператору).

## Тесты

```bash
npm test
```

Запускает интеграционные тесты API (`scripts/test_admin_suite.mjs`). Тесты поднимают backend во временной папке с временной базой данных и случайным паролем администратора — реальная база, `.env`, почта и Telegram не затрагиваются. Письма уходят на локальный тестовый SMTP-сервер, который поднимает сам скрипт, поэтому проверяется настоящая отправка через nodemailer (ссылка сброса, письма-подтверждения).

## Переменные окружения backend

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт API (по умолчанию 8787) |
| `FRONTEND_URL` | URL сайта — для CORS и ссылок сброса пароля |
| `DATABASE_PATH` | Путь к файлу SQLite. На Render нужен постоянный диск, иначе данные теряются при каждом деплое |
| `ADMIN_EMAIL`, `ADMIN_INITIAL_PASSWORD` | Единственный администратор (см. выше) |
| `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USER`, `EMAIL_PASS`, `EMAIL_FROM` | SMTP для писем сброса пароля. Если не заданы, ссылка сброса пишется в лог сервера |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Необязательно: уведомления о новых регистрациях |
| `PAYMENT_*` | Платёжный провайдер (см. ниже) |
| `TRUST_PROXY_HOPS` | Число прокси перед приложением (Render = 1), нужно для корректного rate limiting |
| `SEED_DEMO_USER` | Только для локальной разработки: создать демо-аккаунт с известным паролем |
| `PASSWORD_RESET_RATE_LIMIT_MAX` | Необязательно: сколько запросов на сброс пароля разрешено с одного IP в час (по умолчанию 10) |

### Переменные для реальных платежей

- `PAYMENT_API_BASE_URL` — базовый URL официального API провайдера/агрегатора.
- `PAYMENT_MERCHANT_ID` — Merchant ID вашего магазина.
- `PAYMENT_API_KEY` — приватный API-ключ для создания платежа.
- `PAYMENT_WEBHOOK_SECRET` — секрет подписи webhook.
- `PAYMENT_CREATE_ORDER_PATH` — endpoint создания платежа (по умолчанию `/v1/orders`).
- `PAYMENT_METHOD_MBANK_CODE`, `PAYMENT_METHOD_ELSOM_CODE`, `PAYMENT_METHOD_ODENGI_CODE` — коды методов оплаты у выбранного провайдера.
- `BACKEND_PUBLIC_URL` — публичный URL backend для webhook.

## Безопасность

- Секреты хранятся только в `.env` / панели хостинга, никогда в git.
- Пароли хешируются bcrypt (cost 12); сессии — случайные токены, в базе хранится только их SHA-256.
- Доступ к данным пользователя и admin API проверяется только по токену сессии.
- Подписка активируется только после webhook-подтверждения оплаты с проверкой подписи.
- Повторная активация одного и того же платежа блокируется через idempotency-проверки и ограничения БД.
